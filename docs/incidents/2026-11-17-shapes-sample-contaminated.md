# 事故：目录形状分析的样本被污染成 "0"…"199"

影响：`docs/metrics/` 里 `--shapes` 的一份输出把"样本包"列成了一串数字，等于宣称"我抽了 200 个真实包"而实际什么都没抽到。任何基于那份输出做的分布结论都不可复现。持续时间 47 分钟（2026-11-17 09:12 至 09:59 UTC+8），影响范围仅限本地生成的一份度量文件，未发布到 npm，未影响任何已发布的检查包。

## 时间线

- 09:12 为形状分析加了 `--shapes`，用 npm registry 的搜索接口按下载量取样 200 个包
- 09:31 输出里"样本"一栏是 `0, 1, 2, …`，判断为显示问题，先记一笔
- 09:44 查 registry 原始响应，发现结果是对象而不是数组，键正好是下标
- 09:47 定位到 `Object.keys()` 被用在一个数组上：数组的键就是下标字符串
- 09:52 补上数组归一化，并加一条断言：取到的包名必须能在目录里找到
- 09:59 重跑，200 个样本全部是真实包名，度量文件重新生成

## 根因

`Object.keys()` 作用在数组上返回下标，而取样函数有两个分支：一个返回数组，一个返回对象。写下 `Object.keys(sample)` 时假定走的是对象分支，实际走的是数组分支。类型在 JavaScript 里不报错，`"0"` 是一个合法的包名字符串，于是它一路流到了报告里。

不是"少写了一个判断"，而是**报告没有校验自己的输入**：一份声称"我看了 200 个包"的报告，从来没有检查过那 200 个东西是不是包。

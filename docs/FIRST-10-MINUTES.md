# 十分钟清掉一次积压

给**已经有一堆待审成果**的人看的：不解释原理，只说点哪里、按什么顺序。

适用场景：装完之后打开「成果审阅」，看到几十条待审。

## 第 0 分钟：先看清你要处理的是什么

顶部有两条筛选：

- **状态**：待审 / 通过 / 退回 / 归档 / 全部
- **类型**：全部 / 文档 / 表格 / 图片 / 数据 / 代码 / 其他（每个都带数量）

判断标准只有一句：**需要人读的，是文档和表格；图片、数据、代码多半是中间产物。**
一个真实的 75 条积压长这样：文档 41、数据 14、图片 9、表格 5、代码 2、其他 4。也就是说真正要读的大概 46 条，而且分在 10 个会话里。

## 第 1–3 分钟：先清掉不需要读的

1. 点类型 **数据** → 逐条扫标题，明显是中间产物的按 `z` 归档（或选中后点「归档」）
2. 同样处理 **图片**、**代码**、**其他**
3. 归档随时可逆：切到「归档」筛选，点「重新打开」

这一步通常能去掉三到五成，而且不需要读任何内容。

## 第 3–8 分钟：逐项审阅剩下的文档

1. 点类型 **文档**，再点右上角 **「逐项审阅」**
2. 顶部会显示 `第 3 / 46 项待审`，列表收起，一次只出现一项
3. 每项只做三件事之一：
   - 看完觉得没问题 → `a` 通过
   - 需要改 → 在审阅意见里写清要改什么 → `r` 退回
   - 不需要审 → `z` 归档
4. 决定之后自动进入下一项；`n` / `p` 可以手动跳，`上一项` / `下一项` 按钮同样有效

**快捷键在输入框里不生效**，所以在意见框里打字不会误触通过。

## 第 8–10 分钟：留下记录

- 通过之后，右边可以点「导出验收单」；导出的是一份独立 HTML，含被审阅文件的 SHA-256 与逐项证据，**发给人不需要对方装任何东西**
- 文件事后被改动过，同一份验收单会明确提示「重新审阅当前版本」，而不是假装通过仍然有效
- 需要对方返工时，点「复制意见并打开原会话」——复制的是一段结构化指令：决定了什么、还差哪几项证据、属于哪个 revision

## 几个常见犹豫

**「归档会不会丢东西？」**
不会。归档只是移出待审队列，原件不动，随时可在「归档」里重新打开。

**「通过按钮为什么是灰的？」**
因为这件成果挂着验收包（研究报告四项、表格三项），必填项还没有「勾选 + 书面证据」。面板上会直接写差哪几项，不用悬停看提示。

**「没有验收包的也要填吗？」**
不用。没有挂包的成果可以直接通过或归档；表格类会自动挂上数据验收包，如果不想走它，也可以在包选择里改回「通用验收（无额外检查）」。

**「一定要填证据吗？」**
如果这份成果要交给别人、或者你以后可能被问"当时是怎么核的"，那就填——验收单的全部意义就在这里。如果只是自己留档，归档即可。

---

想先试一遍流程而不想动真实成果：在空队列时点「生成一条示例成果」，它会造一条示例研究报告，带完整四项证据门，走完可以归档掉。

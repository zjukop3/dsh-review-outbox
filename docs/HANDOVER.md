### 2. 发布

发布不是 `npm publish` 就完事。四段时间常数写在 `docs/OPERATIONS.md`，最少要记住：`registry.npmjs.org` 的 dist-tag 会滞后一到两分钟；目录仓库的条目合并后要等它自己重建；市场卡片有 24 小时冷却；运行中的 DSH 进程持有旧插件，装完必须重启才生效。

本机 `.npmrc` 默认指向 npmmirror，所以每条发布命令都要显式 `--registry=https://registry.npmjs.org`。推送用 `npm run push:verified`——它读远端比对，不看退出码，因为这台机器到 github.com:443 一直在抖。

`dsh-vertical-kit/scripts/audit-rules.mjs` 要求每条规则在测试里被观察到两个方向。`test/dogfood.test.js` 要求每个检查在真实文档上不误报。两套都是 `npm run check` 的一部分，红了就是真红了。

### 4. 指标：为什么是 0，以及别把它做上去

北极星指标是"每周被真正审阅并处置的成果数"。现在是 0，因为没有人真的用过。

`docs/adr/ADR-0003` 记了为什么不能加 `--approve-all`：一旦实现者可以随时清空分母，这个数就只剩装饰作用。**接手后最容易被做的一件事就是把它做上去**——加个批量按钮、把老条目标成 expired，两个都能让面板好看，且都能自动化。两者都不做。

下载数同理，见 `ADR-0002`：6,200 次/周听起来像有用户，但离散度检查（变异系数 0.186）说明那是一个自动化客户端的一个频率。

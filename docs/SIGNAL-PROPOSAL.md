# 给目录/市场的信号提案：发布日形状的周数字应带「发布日」标记

**状态**：草案，计划随 2026-12-01 月报正式开 issue（fkysly 在 #13819 的结论里明确邀请「具体的替代信号提案（带可复现的测量）」）。开 issue 前先刷新数字。

## 提案内容（一句话）

列表/市场页的「下载」列，当某个包**单日下载占其周总量 ≥ 50%** 时，显示为「发布日」样式（徽标或斜体）而非裸数字。不改排序，只给读者一个不误读的口径。

## 为什么是这一个信号

1. **它可判定**：只需要最近 7 天的日值序列，npm 下载 API 直接给。不需要新的数据源、不需要维护方做任何主观判断。
2. **它抓住的正是误读的高发形状**：发版日固定开销。实测（2026-11-15）：
   - 全目录抽样（198 包，seed 20261110，30 天窗口）：**19.7% 呈单日 ≥5× 中位数的爆发形**；
   - 自己的包是现成的展品：`dsh-review-outbox` 周下载 1,997、排序 **#318/5,165（前 6.2%）**，但**前两天的下载占 82%**（11-09 单日 1,131 = 发版日 2.3 倍），安静日 36–81 落在底噪带（≤40/天，占全目录 58.6%）。按这个数字排序的人会得出「前 6% 的插件」的结论——而它的安静日形状与没人用无法区分。
3. **成本极低**：展示层加一个条件样式；探测管线已每天拉 npm 数据，加一步日值序列即可。

## 已被明确拒绝的替代项（不再提）

- 换排序口径 / 换信号源 —— fkysly 在 #13819 已给维护者结论：不值得。本提案**不动排序**。

## 复现

```bash
node scripts/ecosystem-snapshot.mjs --shapes 200 --seed 20261110   # 爆发形占比
node scripts/ecosystem-snapshot.mjs --package dsh-review-outbox    # 展品的全量数据
```

原始数字：`docs/metrics/2026-11-15-ecosystem-weekly.json`；方法论：`docs/ECOSYSTEM-BASELINE.md`；月报页：`/ecosystem/`。

## 已知不确定项

- npm 日值有上报滞后（最近两天常为 0；zuwenyin 以 react 四千万下载日同样报 0 验证过）——判定窗口应排除最近两天，用「前 5 天中某一日 ≥50%」。
- 阈值 50% 是拍的，可按维护者口味调；给出的是机制不是常数。
